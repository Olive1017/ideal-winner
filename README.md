# 壳牌订单转换与 SDCC 上传工具

把壳牌的订单 Excel 转成 SDCC 导入模板：每天定时自动备好待上传文件，上传时在「运行」页点一下即可。

## 它做什么

原本的流程：登录壳牌导出订单 → 手工整理成导入格式 → 登录 SDCC → 点十几下传上去。

现在：每天定时自动从壳牌 LMS 导出订单、转换成 SDCC 导入格式并放入待上传队列；上传时在「运行」页点「开始处理」即可（SDCC 登录环节仍需人工完成）。

**流程：定时导出 → 转换 → 待上传队列 → 一键上传。** 出问题会重试、会截图、会记日志。

队列语义：

- 队列里已有文件时，「开始处理」直接上传最新一份；
- 队列为空时，「开始处理」自动先走 导出 → 转换 再上传，一条龙；
- 想无视队列重新拉数据，点「强制拉最新」。

## 快速开始

```bash
pip install -r requirements.txt
playwright install chromium

python main.py
```

首次使用：

1. 在「运行」页选择数据文件夹——壳牌订单、转换结果和归档都放在这里，没选则无法开始处理；
2. 到「设置」页填壳牌 LMS 账号密码、选择车型映射表，并确认项目/模板与 SDCC 导入弹窗里的选项文字完全一致。

## 界面

| 页面 | 用途 |
|---|---|
| 运行 | 数据文件夹、自动准备开关与每日时间、待上传队列、开始处理 / 强制拉最新 |
| 日志 | 按每次执行分组查看，失败带截图 |
| 设置 | 壳牌账号密码、导出配置、项目模板、静默运行、开机自启 |

关闭窗口默认收到托盘，定时任务继续生效。托盘图标会变色：蓝=空闲，黄=运行中，绿=成功，红=失败。

## 转换规则

数据源是壳牌订单的「运单」工作表。

### 日期

以**要求到厂日期**为基准推算：

| 输出字段 | 规则 |
|---|---|
| 客户订单时间 | 要求到厂日期 − 1 天 |
| 计划发货时间 | 要求到厂日期 |
| 计划到达时间 | 要求到厂日期 + 1 天 |
| 导单日期 | 要求到厂日期 |

日期解析不了会直接报错并指出 Excel 行号，不会把 `NaT` 当成字符串写进去。

### 其他字段

- 订单类型固定为「整车运输」
- 体积 = 件数 × 3，重量 = 件数 × 1000
- 客户销售单号取交货单号原值（去首尾空白）

### 车型匹配

交货单号两边都先归一化（取前导数字、补零到 10 位）再匹配。
**归一化后的值只用于查车型，不会写进上传文件。**

车型文件可以不传（全部填「未知」并提示），但一旦传了就必须能读——
文件损坏或缺列会直接报错，而不是静默地把整批车型变成「未知」传上去。

## 自动准备与重试

开启后程序驻留托盘，每天到点自动跑「从壳牌导出 → 转换 → 放入待上传队列」；
上传动作由人在「运行」页触发，不自动传 SDCC。

### 重试

| 错误类型 | 例子 | 处理 |
|---|---|---|
| 可重试 | 超时、页面没加载出来、服务端抽风 | 5 / 15 / 30 分钟后重试，最多 3 次 |
| 不可重试 | 密码错、模板名错、业务校验不过 | 立即失败，等人工 |

可重试失败时文件**不归档**，留在队列里等下次。不可重试才归档，
避免明天又拿同一个坏文件重跑。

部分成功（比如「成功 8 条，失败 2 条」）算成功并记警告，不重传，
否则已经成功的那几条会重复。

## 目录结构

```
ideal-winner/
├── main.py              # 入口：单实例检查 + 日志初始化 + 拉起界面
├── core/                # 业务逻辑，不依赖 UI
│   ├── models.py        # 数据类与错误类型
│   ├── converter.py     # Excel 转换
│   ├── shell_exporter.py # 从壳牌 LMS 导出订单源数据（Playwright）
│   └── uploader.py      # Playwright RPA 上传 SDCC
├── services/            # 支撑设施
│   ├── config.py        # 配置与目录
│   ├── credentials.py   # 密码存取
│   ├── logger.py        # JSONL 日志
│   ├── scheduler.py     # 定时与重试
│   ├── single_instance.py
│   └── autostart.py
├── ui/                  # PySide6 界面
│   ├── main_window.py
│   ├── tray.py
│   ├── workers.py
│   └── pages/
└── assets/
```

一个原则：**core/ 和 services/ 不得 import ui/**。所以没装 PySide6 也能跑核心的转换逻辑。

## 数据存在哪

订单数据放在你在「运行」页选择的**数据文件夹**里：

```
壳牌订单/                          壳牌 LMS 导出的原始订单
SDCC订单/                          待上传队列（文件即状态）
归档/2026-08-10/ok_093015_*.xlsx   传完归档
```

程序自身的文件固定在 `~/SDCC订单工具/`，与数据文件夹分开：

```
config.json   配置（不含密码）
日志/         每次执行的 JSONL 日志
截图/         失败截图
app.lock      单实例锁
upload.lock   任务互斥锁
```

密码存在 Windows 凭据管理器（通过 `keyring`），不会进配置文件、不会进日志、不会进仓库。

## 日志格式

每行一个 JSON：

```json
{"ts":"2026-08-10T09:30:15.123","run_id":"20260810_093015_a3f9c1",
 "level":"INFO","step":"login","status":"success","msg":"登录成功"}
```

选 JSONL 而不是纯文本，是为了以后把日志搬到网页前端时不用重新解析——
前端直接读同一份文件、同一套字段。

## 打包

```bash
pyinstaller main.py --noconsole --onefile --name ShellConvert \
  --icon assets/app.ico --add-data "assets;assets"
```

浏览器用本机已装的 Chrome，没有则回退 Edge，**不打包 Chromium**。
否则 exe 会从几十 MB 直接胀到 300 MB 以上，而公司电脑本来就都装了浏览器。

## 已知限制

- 仅 Windows（开机自启、凭据管理器）；其他平台可跑界面但这两个功能失效
- 无自动更新，换版本需重新发 exe
- SDCC 页面改版可能导致选择器失效，看日志截图定位后改 `core/uploader.py`
- 壳牌 LMS 页面改版同理，改 `core/shell_exporter.py`
