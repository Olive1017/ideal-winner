# 壳牌订单转换与 SDCC 自动上传

把壳牌的订单 Excel 转成 SDCC 导入模板，并每天定时自动传到 SDCC TMS。

## 它做什么

原本的流程：收到壳牌订单 → 手工整理成导入格式 → 登录 SDCC → 点十几下传上去。

现在：选两个文件点一下转换，剩下的每天定时自己跑。

**转换不自动化，只自动化上传。** 因为两个输入文件（壳牌订单、车型映射）都需要人看一眼，
让程序自己去猜该拿哪个文件风险比省的那两下点击大得多。

## 快速开始

```bash
pip install -r requirements.txt
playwright install chromium

python main.py
```

首次使用先到「设置」页填 SDCC 账号密码。

## 界面

| 页面 | 用途 |
|---|---|
| 转换 | 选文件 → 转换 → 预览 → 导出或放入待上传队列 |
| 自动上传 | 开关、每日时间、队列状态、立即跑一次 |
| 日志 | 按每次执行分组查看，失败带截图 |
| 设置 | 账号密码、项目模板、静默运行、开机自启 |

关闭窗口默认收到托盘，定时任务继续生效。托盘图标会变色：蓝=空闲，黄=上传中，绿=成功，红=失败。

## 命令行

排查问题时比界面方便：

```bash
python main.py convert 订单.xlsx -c 车型.xlsx   # 转换并放进队列
python main.py upload                          # 立即上传，实时打印每一步
python main.py config --username 13100000000   # 修改配置
python main.py password                        # 录入密码
python main.py ui --minimized                  # 启动后直接进托盘
```

## 转换规则

数据源是壳牌订单的「运单」工作表。

### 日期

以**要求到厂日期**为基准推算：

| 输出字段 | 规则 |
|---|---|
| 客户订单时间 | 要求到厂日期 − 1 天 |
| 计划发货时间 | 要求到厂日期 |
| 计划到达时间 | 要求到厂日期 + 1 天 |
| 导单日期 | 要求到厂日期 |

> 旧版 README 写的是「以文件创建时间为基准，+1/+3 天」，与代码不符。
> 已按代码实际行为修正。

日期解析不了会直接报错并指出 Excel 行号，不会把 `NaT` 当成字符串写进去。

### 其他字段

- 订单类型固定为「整车运输」
- 体积 = 件数 × 3，重量 = 件数 × 1000
- 客户销售单号取交货单号原值（去首尾空白）

### 车型匹配

交货单号两边都先归一化（取前导数字、补零到 10 位）再匹配。
**归一化后的值只用于查车型，不会写进上传文件。**

车型文件可以不传（全部填「未知」并提示），但一旦传了就必须能读——
文件损坏或缺列会直接报错，而不是静默地把整批车型变成「未知」传上去。

## 自动上传

开启后程序驻留托盘，每天到点把队列里最新的文件传上去。

**队列为空就静默跳过**，只记一条日志。没单的日子不应该报错。

### 重试

| 错误类型 | 例子 | 处理 |
|---|---|---|
| 可重试 | 超时、页面没加载出来、服务端抽风 | 5 / 15 / 30 分钟后重试，最多 3 次 |
| 不可重试 | 密码错、模板名错、业务校验不过 | 立即失败，等人工 |

可重试失败时文件**不归档**，留在队列里等下次。不可重试才归档，
避免明天又拿同一个坏文件重跑。

部分成功（比如「成功 8 条，失败 2 条」）算成功并记警告，不重传，
否则已经成功的那几条会重复。

## 目录结构

```
ideal-winner/
├── main.py              # 入口：无参数启界面，带参数走命令行
├── core/                # 业务逻辑，不依赖 UI
│   ├── models.py        # 数据类与错误类型
│   ├── converter.py     # Excel 转换
│   └── uploader.py      # Playwright RPA
├── services/            # 支撑设施
│   ├── config.py        # 配置与目录
│   ├── credentials.py   # 密码存取
│   ├── logger.py        # JSONL 日志
│   ├── scheduler.py     # 定时与重试
│   ├── single_instance.py
│   └── autostart.py
├── ui/                  # PySide6 界面
│   ├── main_window.py
│   ├── tray.py
│   ├── workers.py
│   └── pages/
└── assets/
```

一个原则：**core/ 和 services/ 不得 import ui/**。所以没装 PySide6 也能跑命令行。

## 数据存在哪

全部在 `%APPDATA%\ShellConvert\`：

```
config.json                          配置（不含密码）
pending/                             待上传队列
archive/2026-08-10/ok_093015_*.xlsx  传完归档
logs/run.jsonl                       日志
logs/{run_id}_error.png              失败截图
```

密码存在 Windows 凭据管理器（通过 `keyring`），不会进配置文件、不会进日志、不会进仓库。

## 日志格式

每行一个 JSON：

```json
{"ts":"2026-08-10T09:30:15.123","run_id":"20260810_093015_a3f9c1",
 "level":"INFO","step":"login","status":"success","msg":"登录成功"}
```

选 JSONL 而不是纯文本，是为了以后把日志搬到网页前端时不用重新解析——
前端直接读同一份文件、同一套字段。

## 打包

```bash
pyinstaller main.py --noconsole --onefile --name ShellConvert \
  --icon assets/app.ico --add-data "assets;assets"
```

浏览器用本机已装的 Chrome，没有则回退 Edge，**不打包 Chromium**。
否则 exe 会从几十 MB 直接胀到 300 MB 以上，而公司电脑本来就都装了浏览器。

## 已知限制

- 仅 Windows（开机自启、凭据管理器）；其他平台可跑命令行但这两个功能失效
- 无自动更新，换版本需重新发 exe
- SDCC 页面改版可能导致选择器失效，看日志截图定位后改 `core/uploader.py`
